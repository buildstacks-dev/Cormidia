# Runtime Capability Matrix

*M10, updated 2026-08-07 UTC (Cursor column added with #338). This table is the
explicit contract for what an org loses or keeps when roles move between runtime
adapters.*

`src/runtime/capabilities.ts` is the matching machine contract. Its
`native | adapter | fallback | unsupported` tiers render inside each selected
turn as `native | adapter-built | fallback (degraded) | unsupported` guidance.
That profile-derived note is descriptive: role tools, permissions, and
approval boundaries remain unchanged.

Capability quality and provider accounting use `docs/episodes/contract.md`: every
adapter invocation is a provider turn with exactly one settlement, missing or
estimated usage stays labeled by quality, and adapter readiness cannot be
inferred from configuration presence alone.

Host scheduling is provider-independent. Phase 5 supports org-scoped launchd
installation and bounded status inspection on macOS; systemd user-timer output
shares the definition/manager boundary but is representation-only until it is
exercised on a supported host. Scheduler lifecycle, empty windows, missed-tick
reconciliation, and status aggregation construct no adapter. Scheduled
provider work enters the ordinary adapter path and must retain one settlement
per provider turn. The canonical platform contract is
[`docs/scheduler/design.md`](../scheduler/design.md).

permission rules and instruction files from `~/.grok`, `~/.claude` and
`~/.cursor`, and its hook runner fails open. Cormidia therefore gives each turn
an isolated `GROK_HOME` **and** `HOME` carrying nothing but `auth.json`, sets
the `[compat.*]` cells and their env equivalents, and re-proves the gate every
turn. Two tradeoffs are deliberate and recorded: the credential file is the one
operator byte carried across (full isolation would break authentication), and
the isolated home is stable per workdir rather than per turn (grok keeps session
transcripts inside it, and a per-turn home broke exact resume).

Terminal provider failures are evidence, not completions. Claude retains an
explicit non-success SDK result (and its usage) even if the SDK iterator then
rejects because the owned CLI exited non-zero. Pi maps terminal assistant
`stopReason: "error"` messages to `failed`, classifying authentication-like
messages as `error_auth`; it never fabricates successful zero-token work.
Cursor maps `result.is_error` / a non-`success` subtype to `failed`, classifying
auth-like text as `error_auth` and workspace-trust text as
`error_cursor_workspace_untrusted`, and a non-JSON stream-json line is a typed
transport failure rather than a silent re-parse. Its transport ends the event
stream only on the child's `close`, so a CLI that exits non-zero surfaces its
stderr instead of finishing as an empty, reasonless `failed` turn — the exact
defect the 2026-08-07 live certification caught.

### Cursor known limitations (#338, live-certified 2026-08-07)

These are documented, not hidden (docs/harness/adding-updating.md §6):

- **The budget cap cannot stop a Cursor turn mid-run.** Usage arrives once, in
  the terminal result. The cap is a turn-boundary check on an estimate.
- **Hermeticity is partial.** Cursor ingests operator-global material — a probe
  observed it reading `~/.cursor/skills-cursor/**` — and the CLI exposes no
  `settingSources: []` equivalent. Those reads are ordinary `Read` tool calls, so
  the gate sees and can deny them, and the role deny list forbids writes under
  `~/.cursor/**`, but the ingestion itself cannot be switched off.
- **An app-authored `.cursor/hooks.json` or `.cursor/cli.json` blocks the turn.**
  Cormidia owns the per-turn Cursor configuration and neither replaces nor merges
  an app's own, because merging would let an app hook answer `allow` on the gate
  channel. Repos using Cursor hooks for their own purposes cannot run Cursor
  turns under Cormidia today.
- **Hook firing is a version-band claim.** The pre-spend handshake proves the
  bridge works; it cannot prove a future build still calls the hook.
  `beforeSubmitPrompt` does not fire headless, so there is no in-turn liveness
  signal. The post-turn executed-versus-allowed cross-check
  (`error_gate_not_observed`) is what makes that residual risk loud instead of
  silent, and `cursor-agent acp` remains the un-implemented fallback rung.

Non-billable readiness requires usable request authentication, not stale
account presence. First-party Claude combines SDK initialization with
`claude auth status --json` in the exact subprocess environment: a concrete
token/API-key source or an authoritative `loggedIn: true` is required, while
email/subscription metadata alone is insufficient. On macOS, Claude.ai
subscription credentials live in the encrypted Keychain rather than a
copyable credential file. Eval therefore gives only the Claude subprocess its
authenticated default HOME/config context; filesystem settings, personal
skills/plugins, and session persistence remain disabled, and a fail-closed tool
sandbox denies host-home reads while re-allowing the eval worktree and confines
writes to that cwd; the Cormidia gate independently denies every tool path outside
the worktree. External Claude providers retain their native credential chain.
Pi first performs its cheap configured-auth check, then resolves the file-backed
credential and requires the concrete non-empty API key that its SDK will send. An expired
OAuth record therefore fails before a model turn instead of being discovered
by one.

**Muse Code is registered but not usable for role work, deliberately.** Its
2026-08-07 certification (`research/2026-08-07_muse-code-adapter-certification.md`,
binary `0.1.0-R708.1`) found no working pre-execution gate seam: `muse exec`
auto-approves headlessly and no managed hook fired across twenty installation
configurations, nor under a verbatim replay of the #340 field probe's own
recovered manifest and environment. That probe's artifacts are real and its
working manifest was recovered and adopted here, so the seam is believed to
exist — it is simply not reproducible on this machine, and a gate that works
only sometimes for reasons nobody can name must never be claimed. **The tier
follows the proof, and the adapter needs no change to earn a better one:** when
a seam is live the per-turn handshake passes and the turn runs gated. The adapter therefore proves the seam per turn and
refuses when it cannot, so the shared two-turn L3 walk (CF-B26-L3) reports
**incomplete**, never pass; `roles.yaml` is untouched and no role may be
assigned until a seam is proven and the record re-run. Readiness
(`cormidia doctor`) reports the same state rather than claiming a ready harness.
What *was* certified: hermeticity by the skills-count delta (23 → 17 skills,
8 → 2 foreign-tagged), the durable-log usage path, and the fail-closed refusal
against the real binary. Re-certification is mandatory on every version bump.
